Sessions stacked down the side, however many you open

The server's status at the top left, the sessions under it, the terminal on the right and the server's files below. The session list scrolls and reorders by dragging; a session also opens in a tab of its own or a split.

  • Save commands as buttons, or write a few lines in the command editor and send them; send one command to many servers and compare what came back
  • Errors, warnings and addresses highlighted, sessions recorded and replayed, files sent with rz and sz
  • Servers in GBK, Big5 or Shift_JIS show right, and Backspace and Delete send what each host expects
  • Two-factor codes typed for you, SSH keys made and deployed in a click, SSH agent and X11 forwarding

The server's files, right under the terminal

The file panel follows the terminal's folder. Drop files in to upload them; thousands of small files go packed and compressed; two servers send to each other directly, nothing through your computer.

  • A code editor built in: tabs, highlighting, completion, and what changed shown before saving
  • Archives, permissions, downloads from a link on the server, and a trash before deleting
  • Routers without SFTP get it installed in a click

How the server is doing, at a glance

CPU, memory, swap, traffic, latency, disks and processes beside the session, over the same connection. The Overview tab puts load, ports, services and containers on one page.

  • Connections, traffic by network interface, trace route and IP locations
  • Alerts when CPU, memory or a disk crosses its limit
  • Drop the caches and compact memory in a click

The server panels you use most, in the client

The parts of BT Panel and 1Panel used every day, done over SSH. Root comes by itself when it is needed, and restarting a service or changing the firewall says what it will touch before it runs.

Containers, images and compose

Create and recreate containers, watch their resources, browse their files; pull, build and push images; deploy and edit compose projects.

  • Start, stop and prune in bulk
  • Networks and volumes
  • Disk usage, events, registries
  • The daemon's settings

Nginx, Caddy and certificates

Site forms and templates, with a failed config check rolled back; Caddy installed, updated and migrated in a click; certificates before they expire.

  • Reverse proxies, static sites, PHP, SPAs
  • Nginx tuning and logs
  • Config backups and restores
  • From Nginx to Caddy

Services, logs and cron

Start, stop and enable systemd services, filter logs by level and time, run a cron job now.

  • Firewall rules
  • Security checks
  • Package updates
  • Disk analysis

MySQL, PostgreSQL and Redis

Reach the server's databases over SSH, browse tables and data, run queries; passwords only in the system's keychain.

  • MySQL and MariaDB
  • PostgreSQL
  • Redis keys

Routers too

OpenWrt and ImmortalWrt are recognized, and the System tab turns into a router's.

  • Interfaces and DHCP leases
  • Port forwards
  • procd services
  • opkg and apk packages

Port forwards, without remembering ssh -L

Local, remote and dynamic forwards are forms. They stay up in the background, start with the app and reconnect by themselves. A server can borrow this computer's network, and the system proxy can split traffic.

  • SOCKS5 and HTTP proxies, reverse proxies, Unix sockets, allow lists and rate limits
  • 21 common setups in a click, and ssh -L/-R/-D commands imported as they are
  • A proxy library, each proxy tested for reach, latency and exit IP

Every server gets a desktop

Turn on desktop mode and the server works like a computer: This PC, a file manager, a task manager, terminals, a browser and an app center, in windows you drag, resize and snap.

  • An AI assistant runs commands on the server: read-only ones by themselves, changes one by one after you confirm, dangerous ones only once you type it out
  • A trash, archives, and copy and paste between servers
  • Your own wallpaper, icon folders and dock

A new computer, and your connections are there

Sign in with GitHub and the connections and settings sync to a secret gist of your own. Computers merge each other's changes item by item; one not used for long asks first whether to merge, take the cloud's or keep its own.

  • Encrypted before it leaves the computer, with your GitHub email address as the sync password, or one of your own
  • Versions kept, previewed and restored; a sync that would delete many waits for your OK
  • Without GitHub: a WebDAV folder (Nextcloud, Jianguoyun) or S3-compatible storage

Bring your servers with you

Import connections and folders from FinalShell, Xshell, SecureCRT and MobaXterm, the hosts of ~/.ssh/config, or a server list in CSV or Excel.

Download

The latest release is on GitHub Releases.

Windows

  • Installer .exe
  • Portable .zip

When SmartScreen says the installer is unsigned, choose More info, then Run anyway. The app updates itself after that.

macOS

  • Apple silicon .dmg
  • Intel .dmg

It is not notarized yet. After dragging it to Applications, run in Terminal:

xattr -dr com.apple.quarantine /Applications/Finallyshell.app

or choose Open Anyway in System Settings › Privacy & Security.

Linux

  • Debian, Ubuntu (x64) .deb
  • Debian, Ubuntu (ARM64) .deb
  • Other distributions (x64) .tar.gz
  • Other distributions (ARM64) .tar.gz

Unpack the archive and run sh install.sh to install it in ~/.local. Remembering passwords needs a keyring such as GNOME Keyring or KWallet.

Build from source

With Go 1.27.3 or newer. go tool mygo dev runs the app and restarts it as the code changes.

git clone -b dev https://github.com/geekoutnet/finallyshell.git && cd finallyshell && go tool mygo dev
