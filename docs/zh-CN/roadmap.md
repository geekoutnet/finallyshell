# 路线图

这份文档记录 Finallyshell（finallyshell 的 `dev` 分支）已经做了什么、正在做什么、接下来做什么，以及每项功能的范围和约束。新增想法时追加到对应的段落；某项开工时移到“进行中”，发布后移到“已发布”并写上版本号。

功能的具体行为写在 [features.md](features.md)，设置项和文件写在 [configuration.md](configuration.md)，代码结构写在 [development.md](development.md)。本文只讲规划。

## 定位和原则

- **SSH 客户端为主，客户端版的服务器面板为辅。** 参照 FinalShell、Xshell、MobaXterm、Termius、WindTerm 的终端和文件体验，再把宝塔、1Panel、DPanel、Portainer 里最常用的服务器管理功能搬进客户端。不在服务器上装任何东西，全部通过 SSH 完成。
- **每项只做最常用的八成。** 不追求功能大全；用得少、维护成本高的部分不做或往后放。
- **生产安全优先。** 用户的服务器都是生产环境：
  - 删除、清理、重建、重启服务、改防火墙、改系统配置等修改操作，执行前一律确认，写清楚会动什么、后果是什么。能撤销的提供撤销，能备份的先备份。
  - 测试一律用模拟后端（可注入的命令执行器、内存里的假服务），绝不在真实服务器上跑修改命令。
  - 拼命令时每个参数都加单引号，名称和 ID 先校验，不把用户输入直接拼进 shell。
- **需要 root 的操作统一走提权。** 顺序见[提权](#提权)：能自动提权就自动，实在提不上去才提示，并告诉用户怎么开通权限。
- **密码和密钥不落地。** 只经加密的 SSH 通道写给 sudo、su 或 `--password-stdin`，不出现在命令行、进程列表、日志、输出窗口和截图里。要记住的存进系统凭据库。
- **两种语言同步。** 界面文案同时写 `locales/en.json` 和 `locales/zh-Hans.json`；文档同时改 `docs/en/` 和 `docs/zh-CN/`，标题和顺序保持一致。

## 进行中

### Docker 页

底部面板新增「Docker」标签，概览的 Docker 卡片有按钮跳过去。顶部分段切换六个模块，由四个 Codex 并发开发，每个只改自己的文件：

| 模块 | 内容 | 文件 |
|---|---|---|
| 容器 | 新建容器表单（端口、卷、环境变量、网络、资源限制，显示对应的 `docker run`）；编辑后安全重建，失败回滚；复制容器；批量启停和删除；实时资源曲线；容器内文件浏览和上传下载；提交为镜像、导出 | `dockerpage_containers.go`、`docker*.go` |
| 镜像 | 拉取（进度、平台、搜索建议）；构建；打标签；推送；导入导出；查看镜像层；清理；被容器占用的镜像默认不能删 | `dockerpage_images.go` |
| 编排 | 项目和服务列表；部署、停止、拉取、重建、下线（删数据卷时强提示）；编辑 compose.yaml 和 .env，保存前备份；新建项目 | `dockerpage_compose.go` |
| 网络、存储卷、系统 | 网络的创建、删除，容器接入和移出；存储卷的创建和清理；引擎信息、磁盘占用、分类清理；实时事件；镜像仓库登录（密码只走标准输入）；镜像加速配置和重启 Docker | `dockerpage_resources.go` |

不做 DPanel 的这些部分：用户和权限（客户端只有自己用）、多 Docker 环境（每个 SSH 连接本来就是一台主机）、应用商店、站点反代和证书（超出 Docker 管理的范围）。

### 提权

一个公共的提权模块，所有需要 root 的功能都用它。每个会话按顺序尝试，记住成功的方式，断开连接后清除：

1. 登录用户就是 root：直接执行。
2. `sudo -n` 可用（免密 sudo）：直接执行。
3. sudo 需要密码：先用这台机器的登录密码试一次，密码错误不重复试，避免触发 sudo 锁定。
4. 弹框输入 sudo 密码，可勾选「记住」，存进系统凭据库。
5. 用户不在 sudoers 里或没有 sudo：在同一个弹框里改用 root 密码，通过 `su` 提权（需要伪终端）。
6. 都不行或用户取消：提示需要 root，并给出可复制的开通命令，例如 `usermod -aG sudo <用户>`（Debian/Ubuntu）、`usermod -aG wheel <用户>`（RHEL/CentOS）。

第一个接入的是「释放内存」，Docker 页合并后把 Docker 的所有操作切过来，之后的新功能从一开始就用它。

## 下一批

Docker 页合并发布之后开工，每组交给一个 Codex。

### 批量执行并汇总

- 从连接列表勾选多台机器（不用先连上），并发执行一条命令或一段脚本，可限制并发数和超时。
- 表格列出每台机器的状态、退出码、耗时和输出摘要，点开看完整输出；失败的一键重试；结果导出成 CSV 或文本。
- 可选择以 root 执行（走提权）；修改类命令执行前确认，列出目标机器数量。
- 和现有的「发送到多个会话」区别：那个是把命令敲进终端，这个是收集结果。

### 服务、日志和定时任务

- **服务（systemd）**：列出所有服务，显示运行、失败、开机自启状态；启动、停止、重启、重新加载、启用、禁用；查看服务的 journalctl 日志和 unit 文件。没有 systemd 的系统提示不支持。
- **日志查看器**：实时跟踪任意日志文件和 journalctl；过滤、高亮关键词、暂停、只看错误；nginx、syslog、auth.log 等常用日志一键打开。
- **定时任务（crontab）**：按用户列出；增删改、启停（注释掉）；把 `*/5 * * * *` 显示成「每 5 分钟」并预览下几次执行时间；保存前备份。

### 磁盘、更新、安全和防火墙

- **磁盘占用分析**：像 ncdu 那样按目录大小逐层查看，找大文件、大日志；删除前确认。
- **系统更新**：显示可更新的包数量，安全更新单独列出；一键更新，实时显示输出；需要重启时提示。支持 apt 和 dnf/yum。
- **安全检查**：SSH 失败登录次数和来源 IP（带归属地）、当前登录用户、最近登录记录、fail2ban 状态和封禁列表。
- **防火墙**：查看和增删 ufw / firewalld 的端口规则；不允许删除放行当前 SSH 端口的规则，防止把自己锁在外面。

## 不做

- 用户和权限管理：客户端只给自己用。
- 应用商店、一键建站：维护成本高，和 SSH 客户端的定位偏离太远。
- 在服务器上安装常驻程序：所有功能都只通过 SSH 完成。

## 开发方式

- **并发开发**：主会话负责调研、拆分、审查、合并和发布；每个模块交给一个 Codex CLI（GPT-6.2 Sol），各自在独立的 Git 工作树和分支里开发。任务说明放在仓库外。
- **避免冲突**：开工前先由主会话搭好骨架（标签、入口、每个模块一个占位文件），每个 Codex 只改自己的文件；文案键用各自的前缀，并插在两种语言文件里各自指定的锚点之后。
- **审查**：合并前逐个检查代码、命令边界、确认弹框、测试和截图（浅色、深色、中英文、宽窄两种尺寸）；修改类命令只认模拟测试的结果。
- **发布**：合并进 `dev` 并推送后，GitHub 先跑完整测试（`go test -race ./...`），再打包各平台并发布 `v2.0.N`；macOS 打包机器排不上队时，其他平台照常发布。
